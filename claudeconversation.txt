5.2 TYPOGRAPHY
--------------------------------------------------------------------------------

ONE FAMILY: Cabinet Grotesk (Fontshare) — display + body + UI.
Loaded once via <link rel="preconnect"> in index.html.
Weights available: 100, 200, 300, 400, 500, 600, 700, 800, 900.

Usage conventions:
- font-display class  → Cabinet Grotesk 700/800 — for headings
- body / paragraph    → Cabinet Grotesk 300 (light) — premium editorial feel
- buttons / CTAs      → Cabinet Grotesk 600
- eyebrows / tags     → Cabinet Grotesk 600/700, uppercase, tracking-[0.32em]
- labels / meta       → Cabinet Grotesk 500, uppercase, tracking-[0.22em–0.28em]

Heading scale (typical):
- h1 hero             clamp ~44px → 100px,  tracking -0.04em, leading 0.98
- h2 section headline 36px → 64px,          tracking -0.03em
- h3 card titles      24px → 34px
- h4 sub-block        18px → 22px
- body                15.5px – 17px,        leading 1.65–1.7

DO NOT add font-script (Alex Brush) accent words. The user explicitly
rejected the rust-pink italic accents (e.g. "feel" inside "you will feel
the results") — they look "ajeeb" and unprofessional. Removed across the
whole site. Class is still in tailwind config for legacy but unused.

6. ANIMATION PATTERNS
================================================================================

ALL animations use GSAP + ScrollTrigger. Lenis (@studio-freight/lenis)
provides the buttery smooth scroll that scrub animations couple to.

6.1 Lenis configuration (in App.tsx)
--------------------------------------------------------------------------------
  duration:       1.8        // longer = more cinematic glide
  easing:         t => Math.min(1, 1.001 - Math.pow(2, -12 * t))
                             // expo-out, deeper exponent than default
  smoothWheel:    true
  wheelMultiplier:0.95       // slightly slower wheel = more deliberate

  lenis.on('scroll', () => ScrollTrigger.update())
  gsap.ticker.add(time => lenis.raf(time * 1000))
  gsap.ticker.lagSmoothing(0)

  Cleanup: lenis.destroy() in useEffect return.

6.2 Standard easings used
--------------------------------------------------------------------------------
  expo.out          for ENTRANCES — fast in, smooth out (1.0–1.4 s typical)
  power3.out        softer entrances (often for cards)
  power3.inOut      for depth/exit transitions (e.g. previous-card scale-down)
  power3.in         for quick exits (preloader curtain peel-up)
  cubic-bezier(0.22, 1, 0.36, 1)   — inline CSS transitions (700–1200 ms)

6.3 Standard durations
--------------------------------------------------------------------------------
  Heading line-mask reveal     1.0–1.3 s, stagger 0.06–0.08 s
  Card stagger fade-up         0.9–1.1 s, stagger 0.08–0.12 s
  Image hover scale            900–1200 ms (cubic 0.22,1,0.36,1)
  Hover micro-interactions     300–500 ms

6.4 The "line-mask" reveal pattern (used everywhere for h1/h2)
--------------------------------------------------------------------------------
  HTML:
    <h2>
      <span class="line-mask"><span>First line</span></span>
      <br/>
      <span class="line-mask"><span>Second line</span></span>
    </h2>

  CSS:
    .line-mask { display: inline-block; overflow: hidden; vertical-align: bottom; }
    .line-mask > * { display: inline-block; will-change: transform; }

  GSAP:
    gsap.set(lines, { yPercent: 110 })
    gsap.to(lines, {
      yPercent: 0,
      duration: 1.1,
      ease: 'expo.out',
      stagger: 0.08,
      scrollTrigger: { trigger: heading, start: 'top 85%' },
    })

6.5 Programs stacking-deck pattern (signature animation)
--------------------------------------------------------------------------------
  Each card pins at top (pinSpacing:false). The next card scrolls UP and
  overlays it. Previous card's INNER (not the pinned outer) fades + scales
  + lifts up on scrub.

  pinTop = window.innerWidth >= 768 ? 110 : 90

  ScrollTrigger.create({
    trigger: card, start: `top top+=${pinTop}`,
    endTrigger: next, end: `top top+=${pinTop + 60}`,
    pin: true, pinSpacing: false, anticipatePin: 1,
  })

  gsap.fromTo(inner,
    { scale: 1, opacity: 1, y: 0 },
    { scale: 0.94, opacity: 0, y: -90,
      ease: 'power3.inOut',
      scrollTrigger: { trigger: next, start: 'top bottom-=80',
                       end: `top top+=${pinTop + 20}`, scrub: 1.4 },
    })

  Each card's enter: y 140 → 0, opacity 0 → 1, scale 0.97 → 1, 1.6 s power3.out

6.6 Method sticky cross-fade timeline (left list + right sticky image)
--------------------------------------------------------------------------------
  Left column: scroll-revealing step rows with active-state highlight
  Right column: <div className="md:sticky md:top-28"> with stacked images,
                 active one has opacity:1, others opacity:0 + scale 1.04
  Active step is detected via IntersectionObserver on each row.

6.7 Cursor (3-layer custom cursor)
--------------------------------------------------------------------------------
  Dot:    fast lerp (0.08 s), rust colour with double drop shadow
  Ring:   medium lerp (0.32 s), mix-blend-difference white border
  Glow:   slow lerp (0.55 s), large radial rust gradient, screen blend

  Hover [data-cursor="hover"] elements → ring scales 2.4x, dot disappears,
                                         glow brightens
  Press → ring scales 0.78
  Disabled on coarse pointer (touch) and prefers-reduced-motion

6.8 VideoTestimonials marquee
--------------------------------------------------------------------------------
  CSS keyframes infinite scroll, cards duplicated 2x for seamless loop:
    @keyframes tac-marquee-scroll {
      0% { transform: translateX(0); }
      100% { transform: translateX(-50%); }
    }
    animation: tac-marquee-scroll 40s linear infinite;
    .tac-cinema-wrap:hover .tac-cinema-track {
      animation-play-state: paused;
    }
  Hover any card → marquee pauses + that video plays muted in place
  Click → fullscreen <video controls autoplay> in modal lightbox

10. DEPLOYMENT — NETLIFY
================================================================================

netlify.toml at repo root configures everything:

  [build]
    base    = "tac-preview"
    command = "npm install && npm run build"
    publish = "dist"        # RELATIVE to base — DO NOT add tac-preview/ prefix

  [build.environment]
    NODE_VERSION = "20"

  [[redirects]]
    from   = "/*"
    to     = "/index.html"
    status = 200
    # SPA fallback — /about, /anything client-routed all serve index.html

  Cache headers for /videos, /assets, /*.webp — 1y immutable

Two ways to deploy:

A. GitHub auto-deploy (recommended):
   1. Sign in at app.netlify.com
   2. Add new site → Import from GitHub
   3. Pick this repo — settings auto-fill from netlify.toml
   4. Click Deploy. Live in ~3 min.
   5. Future pushes to main auto-trigger a rebuild.

B. Drag-drop (no GitHub link):
   1. Run `cd tac-preview && npm run build` locally
   2. Drag the resulting tac-preview/dist/ folder onto app.netlify.com/drop

KNOWN GOTCHA: in netlify.toml, `publish` is RELATIVE to `base`. Earlier we
had `publish = "tac-preview/dist"` which Netlify resolved as
`/opt/build/repo/tac-preview/tac-preview/dist` (double-nested = 404). Fix
was to change to just `"dist"`. Already correct in repo.

  3. Show user the URL — they hover/click to test interactively
  4. After they pick, integrate the chosen option into the main site
  5. DELETE the preview page + any rejected option files

  Don't leave preview pages around — they bloat the bundle.

--------------------------------------------------------------------------------
  - Always group related changes into ONE commit with a comprehensive
    message (not one commit per file).
  - Use the commit style established in git log (descriptive subject +
